여러 사용자 페르소나로 쇼룸을 **실제로 써보며** 보안·UX 결함을 뽑는 도그푸딩 감사다. 읽기 전용 — 코드를 고치지 않는다. 대상: $ARGUMENTS (비면 운영 URL https://moondaon-showroom.vercel.app)

## 페르소나 (최소 4종, 실제로 클릭·입력해서 확인한다)

1. **첫 방문 모바일 고객** — 3초 안에 "여기서 뭘 하는지" 아는가. 첫 로딩 빈 화면·검정 화면·조작 힌트 부재.
2. **꼼꼼한 검토자 (데스크톱)** — 제품·유리·색상을 실제로 갈아끼우며 조합이 깨지는 지점, 되돌리기, 공유 링크 재현성.
3. **악의적 사용자** — URL 쿼리·해시 주입, 없는 id, 범위 밖 치수, `/api/share`·`/s` 파라미터 조작. 서버가 뭘 그대로 믿는지 본다.
4. **현장 영업사원 (아이패드/AR)** — 고객 앞에서 보여주기, "실물 크기로 보기", 네트워크 느릴 때.

## 규칙

- **화면을 실제로 열어 확인한다.** 코드만 읽고 "될 것 같다"로 판정하지 않는다.
- 운영에 쓰기를 남기는 조작(공유 생성 등)은 최소 횟수만. 부하·반복 요청 금지.
- 결함은 **재현 절차 + 실제 관측 + 심각도**로 적는다. 추측은 "미확인"으로 표시.
