# /doc-update

코드 변경 후 어떤 문서를 갱신해야 하는지 점검하고 필요한 파일을 업데이트하는 절차.

## Steps

1. 변경 파일 목록 수집
2. change class 분류
3. 필수 문서 후보 좁히기
4. `PROJECT-STATUS.md`는 최신 상태만 얇게 갱신 (`Recent Changes` 5개 이하)
5. 긴 변경 서술·검증 증거·회고는 `docs/daily/YYYY-MM-DD-<work-unit>.md`에 기록
6. 해소된 placeholder/리스크는 보드에서 낮추거나 `✅` 처리
7. 구조 결정이 있으면 `DECISION-LOG.md` 기록
8. 검증 결과와 남은 리스크 정리
