# SCENE-PLAN — 씬(Entryway) 사실감 로드맵

2026-08-26 조준 판정 기준: 재질 절반·빛 절반·현관 미착수 (완결 경로 0/3). 원칙 — **문이 주인공**, 배경은 "살고 있는 집"의 힌트만. 소품 제작 절차는 `.claude/skills/소품/SKILL.md`.

## 개선 축 (순서대로)

1. **재질** — 단색 면을 질감으로. 벽 미세 요철, 강마루 나뭇결 반사, 현관 포세린 타일. 소스: ambientCG(CC0). 모델 추가 없이 최대 효과.
2. **빛** — ACES 톤매핑 확인, 접지그림자(ContactShadows), 다운라이트·코브 색온도 2700K대 통일. 유리 너머 현관 센서등 은은한 빛(유리 재질감 동반 상승).
3. **현관(유리 너머)** — 항상 프레임 안. 빈 무대 → 생활 공간.
4. **거실 소품** — 카메라 앞. 국룰 배치만 최소로.

## P-E 포근함 (2026-08-27 조사 → 6 phase)

**진단.** 소품이 모자란 게 아니다. ① P-C가 "포근함 핵심"으로 만든 소품 상당수가 **기본 카메라 프레임 밖**이라 0픽셀 기여 중이고, ② 프레임 안 모든 면이 같은 밝기 베이지라 **최암부가 몬스테라 잎**이다. archviz 정설상 아늑함은 밝기가 아니라 대비(warm↔cool, bright↔dark)에서 나온다.

### 프레임 게이트 — (구) 이탈각 ≤30° → **현행: 절두체 투영(ndc)**. 아래는 도입 경위

기본 카메라(`CAMERA` SSOT: position `[1.8,1.5,3.4]` · target `[0,1.15,0]` · fov 45)의 시선축에서 각 소품 **원점**이 벌어진 각도. 화면비 1.63 기준 가로 반각 34°·세로 반각 22.5°·대각 반각 38°이므로 **30°는 모든 축에서 안쪽**이다.

착수 시점 측정값 (doorW=1.25 기본):

| 소품 | 이탈각 | 판정 |
|---|---|---|
| floor-lamp | 54.3° | FAIL — 완전 화면 밖 |
| console | 46.5° | FAIL — 완전 화면 밖 |
| window(+sheer) | 34.5° | FAIL — 좌측에서 잘림 |
| mirror | 34.4° | FAIL |
| rug | 33.7° | FAIL — 실렌더에서 안 보임 |
| 나머지 8개 | 11.7~23.5° | PASS |

의도적 컷오프 소품(프레임 가장자리 근경물)도 **원점은 30° 안**에 두고 지오메트리만 밖으로 뻗게 한다 — 원점이 밖이면 "있는지 없는지 모르는 소품"과 구별되지 않는다.

**보강 1 (P-E3) — 세로 이탈각 ≤19° 동반 조건.** 총각 30°만으로는 모자랐다. 세로로만 27° 벌어진 점도 총각 30°를 통과하지만 세로 반각은 22.5°뿐이라 화면 밖이다 — 러그가 게이트 PASS 후에도 하단에 잘려 실증됐다.

**교체 (2026-08-27) — 각도 프록시 폐기, 절두체 투영으로.** 각도 두 개로도 부족했다. 창이 총 31.6°로 FAIL 났는데 실제로는 화면 안이었다(ndc −0.82) — **구면 각도는 가로 34°·세로 22.5°인 직사각 절두체를 그릴 수 없다.** 프록시를 계속 쓰면 게이트가 거짓 양성을 내고, 그걸 면제로 덮으면 게이트가 거짓말을 배운다. 현행 구현:

- `frameNdc(p)` — 기본 카메라 절두체로 정규화 화면좌표 산출. `FRAME_ASPECT = 1.63`(데스크톱 실측 1.76보다 좁게 = 엄하게), 여유 `x 0.94 / top 0.94 / bottom 0.86`(하단 UI 슬라이더 몫).
- `inFrame(p)` — 원점이 화면 안인가. 이게 통과 조건.
- `SceneProp.offFrame?: 'cutoff' | 'light'` — **의도적으로** 밖에 두는 소품의 사유. `cutoff`는 원점만 밖이고 지오메트리가 안으로 뻗는 근경물, `light`는 등기구가 안 보이고 광원만 유효한 경우. 안 달면 안에 있어야 한다.
- 역방향 테스트도 건다 — **화면 안인데 `offFrame`이 붙어 있으면 FAIL**(낡은 면제 표시 제거 강제).

**모바일 카메라 + 제품 프레이밍 게이트 (2026-08-27).** 소품보다 먼저 **제품**을 잰다 — `frameNdc`가 카메라·화면비를 인자로 받게 일반화하고, 문 개구부 4모서리가 데스크톱·모바일 양쪽에서 프레임 안에 드는지 테스트한다. 데스크톱은 세로축 0.90으로 이미 빠듯한데(P-E3의 `target.y` 하향 대가) 상한은 현행을 통과시키는 0.93으로 두고, **모바일이 데스크톱보다 끼면 FAIL**이라는 상대 조건을 함께 건다. `CAMERA_MOBILE`(fov 54)·`FRAME_ASPECT_MOBILE`(0.888)이 SSOT.

**ㄱ자(개방형) 자동 숨김 (2026-08-27).** ㄱ자를 고르면 벽 두 장이 사라진다 — 전실 우측벽과 개구 우측 벽판. 거기 기댔던 소품은 새로 서는 부스 가벽을 뚫거나 허공에 뜬다. 소품 id를 열거하지 않고 **좌표로 판정**한다(`inRemovedCornerWall`: `x > doorW/2 + 0.04 && z < 0.2`) — `?edit=1`로 옮기면 id 목록은 바로 낡지만 규칙은 따라오기 때문이다. 다른 중문에선 조건이 꺼져 전부 복귀하고, 그 복귀를 테스트가 보증한다. 예외는 해당 소품에 `modes.openCorner.hidden: false`.

**카메라 변경 (P-E3).** `CAMERA.target` y 1.15 → **0.98**. 카메라 높이 1.5m에서 시선축이 5.2°만 내려가면 **바닥은 3.3m 밖일 때만 프레임에 든다** — 거실 깊이가 3.5m라 러그를 어디에 깔아도 안 보이는 기하학적 벽이었다. 남아돌던 천장을 내주고 바닥을 얻는다. 문 상단(2.34m) 여유 2.3° 잔존.

**판정 절차 주의.** `SceneProps`가 `useState(SCENE_PROPS)`라 Fast Refresh가 옛 좌표를 보존한다. **좌표를 고친 뒤 실렌더 판정은 하드 리로드 후에만 유효하다** — P-E3에서 이걸로 한 번 오판했다.

### 배치 정본 (2026-08-27 주인님 `?edit=1` 재배치 — 채택)

주인님이 편집기로 직접 잡은 배치를 정본으로 삼는다. 게이트 수치가 아니라 이 배치가 기준이다.

- 소파 z 0.9 → **1.95** · 몬스테라 좌측 → **우측(abs x 1.98)** — 둘 다 원점은 프레임 밖, 지오메트리는 안. `offFrame: 'cutoff'`
- 스탠드 z 0.15 → **2.94** — 등기구는 화면 밖, 광원(distance 2.6)이 소파를 비춘다. `offFrame: 'light'`
- 창 z 0.48 → 0.8 (프레임 안, ndc −0.82) · 러그·현관 소품 전반 재배치 · 커튼 삭제

**남은 사실 하나** — 우산꽂이(abs x 0.75)·코트 후크(x 0.77)는 일반 중문에서 개구부 벽에 가려 0픽셀이다. 개구부를 통과한 시선이 현관 뒷벽에 닿는 범위는 x −1.05 ~ −0.04뿐이다. ㄱ자에서는 자동 숨김이 걸린다.
