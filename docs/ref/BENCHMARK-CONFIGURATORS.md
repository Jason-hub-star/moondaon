# 타 업계 컨피규레이터 벤치마크

목적: **다른 도메인에서 아이디어를 가져온다.** 창호 업계만 보면 우리보다 못한 것만 나온다 — 자동차·가구·커스텀 소비재·견적 서비스까지 넓혀 훔칠 패턴을 찾는다.

조사 원칙(`~/.claude/CLAUDE.md` 「조사」): ① 1차 출처를 연다 ② **주장과 사실을 가른다** — "업계 최고 3D" 같은 건 버리고 "옵션 충돌 시 자동 보정한다" 같은 구조적 사실만 남긴다 ③ 내 것과 대조한다 ④ **판정으로 닫는다**(채택/비채택 + 사유 한 줄). 비채택 사유를 안 남기면 다음에 같은 조사를 반복한다.

### 1-D 자동차 (Porsche / Tesla / BMW / Polestar / Audi / Rivian)

**먼저 가름**: 6곳 중 우리와 **같은 렌더 계열(클라이언트 실시간 3D)은 Rivian 하나뿐**이다. BMW·Audi는 서버 GPU 픽셀 스트리밍(WebRTC+Unreal), Porsche는 클라우드 이미지 온디맨드, Tesla·Polestar는 사전 렌더 이미지다. **따라서 이 도메인에서 훔칠 것은 "렌더 방식"이 아니라 UI 상호작용이다.**

| 확인된 사실 | 대상 |
|---|---|
| **충돌 옵션을 자동 해제하고 hover 툴팁으로 사유 안내** | BMW |
| **빌드 상태 전체를 URL에 base64 JSON으로 직접 인코딩** — 서버 저장 불필요(실제 디코드로 검증) | Polestar |
| 옵션별 **실시간 가격 델타**(색상 +$2,500 식) | Rivian |
| 8자리 "Porsche Code" / "Build Code" — 서버 발급 공유 코드 | Porsche·BMW |
| 조합당 약 400장 사전 렌더 이미지 시퀀스 | Polestar |

**우리 규모엔 과한 것**: ① 서버 GPU 스트리밍(세션 1개 = GPU 1개) — 이미 클라이언트 실시간 3D라 불필요 ② 조합별 400장 사전 렌더 — 우리 조합 수(7축)에선 저장·렌더 비용이 폭발하고, 실시간 3D가 이미 구조적으로 푼 문제라 **후퇴**다.

### 조사 운영에서 드러난 제약 2가지 (다음 조사 때 반드시 반영)

1. **WebSearch 예산이 세션 단위로 소진된다(200/200).** 웨이브 2 중반에 바닥나 이후 갈래는 신규 검색 없이 WebFetch만으로 돌았다. → **병렬 갈래 수를 늘리는 것보다 갈래당 질문을 좁히는 게 낫다.**
2. **서브에이전트의 브라우저 자동화가 메인 세션과 탭을 공유한다.** 한 갈래가 조작 중 내가 열어둔 무관한 페이지로 탭이 두 번 튀었고, 해당 갈래가 안전 판단으로 자동화를 중단했다. → **브라우저 실사용 검증은 메인 세션이 직접 하거나, 한 번에 한 갈래만 쓴다.**

### 2-B 아파트 도면 데이터 — **비채택 확정**. 다만 대체재가 우리에게 이미 있다

웨이브 1의 최대 실마리("평형 고르면 현관 치수 자동")를 데이터로 뒷받침할 수 있는지 판정한 결과 — **못 한다.**

| 소스 | 판정 | 사유 |
|---|---|---|
| 한샘 홈플래너 2.0 (5만 세대) | **막힘** | 자사 내부 데이터, 외부 API 없음. 게다가 **오프라인 매장 상담 도구**지 온라인 셀프서비스가 아니다 |
| 오늘의집 3D | **막힘** | 완전 셀프·온라인이지만 자사 내부 데이터, 외부 개발자 API 없음 |
| 세움터·정부24 건축물현황도면 | **막힘** | 평면도 열람 제도는 실존하나 **본인 소유·거주 건물만, 건별 본인인증**. 대량 확보용이 아님 |
| 아실 | **막힘** | `robots.txt`가 네이버봇 외 **전체 크롤러 차단** |
| 공공데이터포털 공동주택 API | 부분 | 주소·면적·난방 등 **속성**은 있으나 평면도·개구부 치수 제공 근거 못 찾음 |
| 직방·호갱노노·국토부 실거래가·한국부동산원 | **미확인** | WAF 차단 + WebSearch 예산 소진으로 약관 원문 미확보 |
| 평형별 현관 규격 표준자료(법령·LH/SH·논문) | **미확인** | 예산 소진으로 착수 못함 |

**그런데 이 실패가 결론을 바꾸지 않는다.** 우리에게 필요한 건 도면 DB가 아니라 **시작점**이고, 그 재료는 이미 `docs/ref/KKART-PATTERN.md`에 있다:

- 현관 유형 분포 — 복도형 **70%** · 개방형 16% · ㄱ자 8% · 원룸 6% (쇼츠 50편 실측)
- 개구폭 중앙값 **1,214mm**, 복도폭 ≈ 개구폭 + 500~600mm
- 현관 깊이 1.2~1.8m, 타일 단차 40~50mm
- 도면 12건 교차검증

즉 **"우리 집 현관이 어떤 형태예요?" 3~4지선다**면 도면 DB 없이도 같은 효과(시작점 + 치수 프리셋)를 낸다. 남의 5만 세대 DB를 부러워할 일이 아니라 **우리가 이미 가진 실측을 온보딩으로 꺼내 쓰는 문제**다.

### 2-C 익명 찜·비교·복귀 — "링크가 곧 상태"

라이브 조작으로 직접 확인(검색 예산 소진으로 브라우저 실측이 1차 출처가 됨).

| 대상 | 로그인 없이 되나 | 확인된 동작 |
|---|---|---|
| Brilliant Earth 하트→Compare | **된다** | 하트 클릭 = 위시리스트 +1 **AND** Compare 탭 카운트 동시 증가(둘이 한 기능). 로그인 모달 안 뜸. 비교는 **나란히 카드 나열**(이미지+스펙+가격+CTA), 슬라이더·오버레이 아님 |
| Nike By You 초안 저장 | **된다** | 3D 빌더 진입에 로그인 불필요. "Share Your Design" → **Copy Link / Save Image**. **"계정에 저장" 개념 자체가 없고 링크가 저장소다.** 구매만 로그인 |
| Blum My Projects | **로그인 필요** | B2B 트레이드 계정 전제 |
| 오늘의집 스크랩 | **로그인 필요** | 비로그인 클릭 시 `sign_in?redirect_to=`로 즉시 리다이렉트(확정) |

**공통 결론**: 로그인 없이 저장이 되는 곳은 **전부 "서버 계정"이 아니라 "링크가 곧 상태"** 였다. 우리는 URL 해시 복원을 이미 갖고 있으므로 찜·비교·복귀 3종이 **해시에 슬롯을 더 얹는 것**으로 끝난다 — 서버 스토리지·계정·이메일 수집 0.

### 이미 하고 있던 것 — 조사가 확인해준 것

- **URL에 상태 인코딩** → Polestar(base64 JSON 직접 인코딩, 실제 디코드로 검증)·Masonite·Vans·Nike와 동일 구조
- **제약을 회색 처리가 아니라 목록에서 제거** → Therma-Tru와 동일(우리는 카드 allowlist + UI 필터)
- **로그인 없는 탐색** → 확인된 12곳 **예외 없이** 같은 구조
- **클라이언트 실시간 3D** → 자동차 6곳 중 우리와 같은 계열은 **Rivian 하나뿐**
- **AR 벽 앵커** → Threekit의 3모드(Horizontal/Vertical wall-to-wall/Vertical ground-to-wall) 중 vertical에 해당

### A3 실행 가능성 — 방은 이미 파라미터, 없는 건 충돌 검사 (2026-08-28 판정)

프리셋으로 방 구조를 바꾸려면 소품이 따라와야 한다. **절반은 이미 돼 있다**:

- `WALL_PARAMS`(현관 여유폭·깊이·천장고·단차)로 방이 파라메트릭
- 소품 `anchor: doorL|doorR` — 문폭 따라 x 자동 이동
- `modes.openCorner` — 모드별 좌표 오버라이드

**없는 것: 충돌 검사.** 지금은 사람이 손으로 좌표를 계산해 "안 겹치네"를 확인한다(신발 두 켤레가 0.014m로 포개진 사고가 그래서 났다). 프리셋으로 방 크기가 바뀌면 소품이 벽을 뚫는다.

필요한 건 물리엔진이 아니라 **경계 검사 한 겹** — 기존 게이트 3종과 같은 계열이다:

| 검사 | 내용 |
|---|---|
| 벽 관통 | 소품 AABB가 방 안에 드나 (벽면은 `WALL_PARAMS`+`doorW`에서 계산) |
| 소품끼리 | 두 AABB가 겹치나 (매트·러그처럼 납작한 건 제외 — 위에 올라가는 게 정상) |
| **문 궤적** | **여닫이 4종**(`abs_hinged` 1 + `swing_bi_directional` 3)은 회전 부채꼴 안이 비어야 한다. 슬라이딩 7종은 벽을 따라 미끄러지므로 "문 앞 바닥"만 |

**선결 조건**: 소품 치수가 렌더러 안에 박혀 있어 데이터 층이 크기를 모른다 → `props.data.ts`에 `size`를 올려야 한다.
