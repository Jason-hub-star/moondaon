## 채택 개선 (전부 적대적 반박 통과)
1. **P1 분할**: P1a 하드코딩 3연동 렌더+개폐(뼈대) / P1b 카드 파이프라인+5축 UI. 반박("커밋 늘어남")은 비용 미미로 기각
2. **1 unit = 1m 규약을 P1부터 강제** — AR 실물 스케일의 전제 (GLTF/USDZ 미터 규약)
3. **AR은 정적 내보내기** — USDZ 애니메이션 소실 확인(three.js #23415) → 버튼 라벨 "실물 크기로 보기"로 기대 관리
4. **ABS는 방문(여닫이 실내문)** — 현관 목업이 아니라 방문 프레임 씬 분기 (P5)
5. **URL 상태에 `v` 버전 필드 + 카드 id 불변 규약** — 옛 공유 링크 보호
6. **hex는 근사 표시 유지** — 사진 화이트밸런스 왜곡, 상대 구분값으로만 사용. 제조사 색상코드 매핑은 v2
7. **캡처 프레임드랍 대비** — 실시간 MediaRecorder 기본 + 무거운 씬은 프레임-바이-프레임 오프스크린 렌더 옵션 (P6)
8. 기역자 코너 = 90° 고정 근사 (JSON must_confirm 항목, 실측 시 교체)

## 크럭스 (불가역, 계획으로 못 닫음)
**프로시저럴 렌더가 "실물 같음"(고급 브랜드 전환의 전제)에 도달하는가.**
실패 시 전체 가치 붕괴 — 모델링 방식(R1-04) 재베팅 필요.

## 킬-실험 (크럭스 게이트, 가장 싼 것)
1. **[P1a 종료 시] 실물감 판정**: 3연동 1종을 리플렛 실사진과 같은 앵글로 나란히 스크린샷 → 주인님 1회 판정. 비용: P1a 안에서 0원. FAIL이면 P2 착수 금지, 재질·모델링 재수렴
2. **[P6 착수 전] 영상AI 절감 검증**: P1 뼈대 6초 녹화 1편을 영상AI에 레퍼런스 입력 → 프롬프트-only 대비 품질·토큰 비교. "토큰 절감"은 현재 주장이지 사실 아님
