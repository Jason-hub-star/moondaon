## 결론

**SSOT에서 화면으로 안 넘어온 항목 17건. 앱을 깨뜨리는 치명은 없다.** 대신 성격이 다르다 — 1차 감사(`AUDIT-2026-08-27.md`)가 "앱이 부서지는 결함"이었다면, 이번 것은 **"고객이 결정해야 할 축이 화면에 아예 없다"**는 누락이다. 가장 큰 셋은 ① 하부레일(문턱) ② 문틀 프레임 폭 ③ 강화유리 — 셋 다 리플렛 전 제품 페이지에 사양이 박혀 있고, 외부 구매 체크리스트에서도 가격·시공을 가르는 항목으로 나온다.

**"SSOT PDF"는 존재하지 않는다.** 정본은 `assets/리플렛자료/` 의 HEIC 원본 5장 + `리플렛_텍스트_정리.json`(구조화 판독본) + `팜플렛-2026-08.png`(2026-08 신판)이다. 이 감사는 JSON 정본 전문을 기준으로 대조했다.

## 높음 — 결정 축이 없음

### H1. 하부레일(문턱) 축이 통째로 없다
SSOT는 제품마다 레일을 다르게 명시한다 — 3연동 `하부 프레임 7MM / 20MM 운영`, 원슬 `하부레일 알루미늄 25X5`, 자동 3연동 `7MM / 10MM / 무레일`, 자동 원슬 `6MM / 무레일`. 카드에도 UI에도 필드가 없다.

- 재현: 어느 제품을 골라도 우측 패널에 레일·문턱 관련 항목 0개.
- 왜 큰가: 문턱은 발 걸림·청소·로봇청소기·외풍을 가르는 항목이고, 업계 체크리스트가 "바닥 레일 높이 확인 필수"로 첫 줄에 놓는다. 무레일은 상급 옵션이라 견적도 갈린다.
- 심각도: 높음 (SSOT 4개 제품 명시 + 구매 결정 1순위)

### H2. 문틀 프레임 폭 선택·표기 없음
SSOT: 3연동 `알루미늄 117mm / 랩핑문틀 132·140mm`, 자동 3연동 `140mm`, 원슬 상부 `43×45`, 자동 원슬 상부 `80×110`, 스윙 `65×20`. 카드는 `frameDepthM` 단일값 고정(예: `slim-3track-19` = 0.117)이고 화면엔 숫자 자체가 안 뜬다.

- 재현: 초슬림 3연동 선택 → 117/132/140 중 고를 방법 없음. 132·140(랩핑문틀)은 존재조차 화면에 없다.
- 왜 큰가: 문틀 폭은 **벽 두께에 맞춰 고르는 항목**이다. 실측 없이 117로 확정된 화면을 고객이 보고 있다.
- 심각도: 높음

### H3. 5T 강화유리 옵션 없음 + 망입 강화불가 규칙 미구현
SSOT가 모든 유리 페이지에 반복한다 — `5T강화유리 옵션은 별도 (망입은 강화불가)`.

- 재현: 유리 11종 어디에도 강화 토글 없음. 망입 3종(`steel-mesh`·`clear-titanium-mesh`·`bronze-titanium-mesh`)은 카드에 `mesh: true`가 있지만 강화 옵션 자체가 없어 규칙이 쓰이는 곳이 없다.
- 현재 유일한 강화 표기: 스윙 2S·스윙+픽스창 제품 설명줄의 "강화유리 기본" (SSOT `양개도어 주문시 강화유리 기본적용` 반영 ✅).
- 심각도: 높음 (안전 + 가격)

### H4. "양방향" 스윙이 한 방향으로만 열린다
제품명이 `베젤 스윙 도어(양방향)`이고 SSOT `swing_bi_directional` = "힌지를 중심으로 **양쪽 방향** 회전"인데, 개폐 슬라이더가 `min=0 max=1`(`App.tsx:291`)이라 반대 방향을 볼 수 없다.

- 재현: 스윙 2S 선택 → 폭 1600mm → 개폐 슬라이더 끝까지 → 두 문짝 모두 전실(안쪽) 방향으로만 회전. 슬라이더를 왼쪽 끝으로 되돌리면 닫힘일 뿐 반대 개방이 아니다.
- 부수 관측: 완전 개방 시 좌측 문짝이 전실 신발장 앞을 덮는다. SSOT의 검증 항목 `문짝 회전 반경과 양쪽 간섭 여부 확인`이 게이트로 존재하지 않는다 — 관통 여부는 각도상 애매해 **미확인**으로 남긴다.
- 심각도: 높음 (제품의 이름이 곧 미구현 기능)

### H5. 3연동 디바이딩 7종이 자동·ㄱ자·간살에서 사라지고, 간살엔 없는 디자인이 뜬다
근본 원인은 패턴 카드의 `motions:` 가 **렌더 방식 id**로 걸려 있다는 것이다. 실제 문짝 계열은 같은데 motion id가 달라 필터에 걸린다.

| 제품 | motion id | 디자인 칩 수 (실측) |
|---|---|---|
| 초슬림 3연동 1.9 / 베젤 1.1 | `sliding_multi_panel` | 17 |
| 자동 실내중문 (3연동) | `automatic_sliding` | **9** |
| 3연동 기역자 중문 | `sliding_multi_panel_corner` | **9** |
| 간살 도어 | `louver_sliding` | **9** |

빠지는 7종 = `grid-2x3`·`mondrian-a/b/c`·`v-dense`·`v-grid`·`waist-double` — 리플렛 IMG_6279 "3연동 디자인/디바이딩" 전량이다. SSOT는 ㄱ자·자동중문을 3연동과 **동일 사양**(문틀 117/132·140, 문짝 19×32)으로 적고 있어 디자인이 달라질 근거가 없다.

반대 방향 오류도 같은 원인에서 나온다. 간살 도어의 실측 디자인 목록은:
> 아치 + 하부 몰딩 / 아치 + 하부 고시 / 아치 (스팬드럴 유리) / 아치 (스팬드럴 고시) / 비대칭 세로 2분할 / 고시형 / 오픈형 / 디바이딩 상부격자 / 디바이딩 허리바

SSOT 간살 페이지의 디자인은 `오픈형 / 가로 1줄 / 가로 2줄` 3종뿐이다. 즉 **없는 아치 4종·고시형이 뜨고, 있는 "가로 2줄"(`waist-double`)은 3연동 전용이라 못 고른다.**

- 심각도: 높음 (팜플렛에 없는 조합을 고객이 주문 가능한 것으로 본다 — 1차 감사의 주문가능성 제약과 같은 부류)

## 중간 — 제품·정보 누락

### M1. 히든 행거 + 펫도어가 통째로 없다
SSOT `abs_collection_2`(IMG_6284 우측 페이지) 전체가 미반영이다. 제품 카드 없음, 옵션 없음.
- 히든 행거: 레일이 도어 뒤에 숨는 슬라이딩. 제약도 SSOT에 다 있다 — 양방향 댐퍼 적용 시 도어 최소 750mm, 콘크리트·보강 벽체 권장, 행거 철물 세트 판매, **방음 목적 아님**.
- 펫도어: 고정자석·모헤어 브러시·끼임/감금 방지·냉난방 절약.

### M2. 원슬 1SD/2SD/4SD 변형이 없어 2400mm가 단짝 한 장으로 그려진다
제품 카드 `one-sliding`은 이름이 `1SD/2SD/4SD`인데 `panels: 1` 고정, 폭 범위는 0.8~2.4m다.
- 재현: 원슬라이딩 → 폭 2400mm → 개폐 최대. 폭 2.4m·높이 2.3m짜리 유리 문짝 **1장**이 좌측 벽 앞으로 밀려나며 액자 벽면을 덮는다.
- 실물에서 2.4m는 2SD/4SD로 나눠야 성립한다. 패널 수 축이 없어 실존하지 않는 제품이 렌더된다.

### M3. 자동중문 — 원슬 변형 없음 + 세일즈 스펙 화면에 0
SSOT는 자동중문을 `3연동 / 원슬라이딩` 두 갈래로 적고, 옵션 근거를 길게 붙인다(대기전력 0.8W 이하, Geariss BLDC, 감속기·구동벨트 제거로 저소음, 개폐 중 충격감지 이중보호 정지, TDU 일체화). 앱은 3연동 하나뿐이고, 이 문구는 화면 어디에도 없다. 자동중문은 최상위 가격대라 설득 근거가 곧 전환율이다.

### M4. 높이(H)가 화면에 없다
SSOT는 제품마다 `H 2300` / 스윙 `H 2350`을 명시하고 카드에도 `maxHeightM`로 들어 있다(`specFrom`이 그대로 씀). 그런데 우측 패널 치수 섹션은 가로 슬라이더 하나뿐이라 **높이 숫자가 한 번도 노출되지 않는다**. AR 진입 가이드에만 나온다.

### M5. 구간별 사이즈 A~D가 3연동 3제품에만 뜬다
`sizeZone()`은 `motion === 'sliding_multi_panel'` 일 때만 표시된다(`App.tsx:402`).
- 실측: 초슬림1.9·베젤1.1·커스텀아치는 `치수 — 1200mm · A구간 (1200~1400)` ✅ / 자동중문·ㄱ자·간살·스윙·원슬·ABS는 `치수 — 1200mm` 만.
- 간살은 구간표가 아예 다르다 — SSOT `A.1000~1100 / B.1201~1300 / C.1301~1400 / D.1401~1500`. 앱 슬라이더는 1000~1500 연속이라 **팜플렛에 없는 1101~1200 구간을 그대로 고를 수 있다**(팜플렛 인쇄 자체의 공백일 가능성 — 문다온 확인 필요).

### M6. 자동 실내중문에 손잡이 3종이 뜨는데 3D엔 안 그려진다 (유령 컨트롤)
- 재현: 자동 실내중문 → 손잡이 "고급형 일체형" 클릭 → 3D 문짝에 손잡이 없음. `DoorModel.tsx:82`가 `handleLengthM={0}`으로 고정(자동문은 센서 개폐 — 실물 관행상 맞다).
- 문제는 선택이 살아 있다는 것이다. 공유 해시에 `handleId: integrated`가 그대로 실려 나가고, 고객은 고른 것이 반영 안 된 화면을 본다.
- 옳은 처리: 자동중문에서 손잡이 섹션을 숨긴다(ABS에서 유리·디자인을 숨기는 `isAbs` 분기와 같은 방식).

### M7. ABS 여닫이에 슬라이딩용 손잡이 3종이 뜬다
접착식 300mm·일체형 900mm·반달은 SSOT상 슬라이딩·스윙 중문 하드웨어다(리플렛 `부속 기타사양`, 팜플렛 p5 `기본운영 하드웨어`). ABS 여닫이 도어에 붙는 것은 레버형 손잡이·도어록이다. 실측: ABS 선택 → 손잡이 3종 노출, 일체형 선택 시 문짝에 세로 바가 붙는다.

### M8. ABS 발포 문틀 8종·가스켓 3색 미반영
SSOT `문틀 110 / 130 / 140 / 155 / 175 / 195 / 210 / 230mm`, `발포 가스켓 백색 / 검정색 / 황토색`. 카드는 `frameDepthM: 0.14` 하나로 고정. ABS는 벽 두께에 문틀을 맞추는 제품이라 이 8종이 사실상 주문 사양이다.
